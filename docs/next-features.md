# 下一批功能：搵樓模式

三樣嘢，用現有數據同現有資料庫結構，唔使加任何新來源。

決定嘅理由：香港啲睇樓 app（中原、美聯、28Hse）全部係「搵盤」工具，
**冇一個幫你管理你已經睇緊嗰幾個盤**。而一個人搵緊樓嗰 1–3 個月，
係佢一世入面唯一會日日入嚟嘅時候 —— 要服務好嗰段時間。

---

## 1. 比較表（1–2 日）

揀 2–4 個收藏咗嘅樓盤，並排睇。

```
                頌真閣      和喜樓      新蒲崗大廈
分數             81          49          75
　環境           78          41          72
　交通           50          50          50
　配套           92          92          88
山 / 水        東南 389米  西南 1.2km   北 620米
坐向           子山午向    乙山辛向    卯山酉向
飛星格局        旺山旺向    雙星到向    上山下水
九運            當運旺財    當運平平    當運平平
入伙年份         1969        2022        1975
屋苑            —           和田邨       —
```

- 入口：收藏面板加一個「比較」掣
- 手機上橫向捲，第一欄（項目名）固定唔郁
- 每一行最好嗰個用色highlight
- 可以分享成一條 link（對方見到同一張表）

**唔使加任何數據** —— 全部欄位喺圖磚入面已經有。

---

## 2. 筆記、自己打分、狀態（1–2 日）

睇樓當日真正用得著嘅嘢。

每個收藏咗嘅樓盤可以加：

| 欄位 | 樣式 |
|---|---|
| **自己打分** | ★★★☆☆（你實際去到覺得點，同風水分無關） |
| **筆記** | 自由文字 —— 光線、噪音、樓底、對面有咩、經紀講咗咩 |
| **租金／售價** | 自己輸入 |
| **狀態** | 想睇 / 睇咗 / 唔要 |

清單按狀態分組：

```
想睇 (3)   頌真閣、XX閣、YY苑
睇咗 (2)   和喜樓 ★★★☆☆、新蒲崗大廈 ★★☆☆☆
唔要 (1)   ZZ大廈
```

**資料庫已經預咗** —— `saved` 表入面個 `note` 欄位起 schema 嗰陣已經有，
加 `my_rating`、`price`、`status` 三個欄位就得，唔使搬任何嘢。

分享清單嗰陣連埋筆記同評分一齊 share —— 買樓好少一個人決定，
呢個本身就係天然嘅邀請機制。

---

## 3. 同屋苑邊座最好（半日）

```
和田邨　4 座
　和樂樓　58 分　★ 全邨最高
　和喜樓　49 分
　和逸樓　47 分
　和滿樓　45 分
```

**點解只做呢個排名，唔做區內／全港排名：**

「贏全港 97%」已經係最強嗰個數字，分享卡同分享文字都有。再加「黃大仙區排
第 312 / 1,539」只會製造矛盾 —— 一幢樓可以係全港 97%，但喺一個好區入面排中游，
兩個數會令人更亂。

但「同一個屋苑邊座最好」唔同：佢對應一個人**真正要做嘅決定**。
409 個屋苑、2,582 座嘅數據已經喺 `estates.json` 同圖磚入面。
