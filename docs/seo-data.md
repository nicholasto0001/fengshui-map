# SEO 頁面：有咩數據可以用

開工之前嘅調查。結論喺最底。

---

## 一、28Hse 做啱咗咩

睇佢個**結構**，唔係抄佢啲字。結構係公開嘅事實，字係佢嘅財產。

**三層 URL，每一層都係一版真嘢：**

```
/estate/                    總目錄
/estate/d3                  新界
/estate/d3/dg40             西貢、清水灣          ← 172 個屋苑，170+ 條內部連結
/estate/detail/…-27376      單一屋苑
```

麵包屑：`地產主頁 > 屋苑成交 > 新界 > 西貢,清水灣`

**四樣佢做得啱：**

1. **每一層都係一條真 URL**，唔係 JavaScript filter。Google 行得到落去。
2. **一版 hub 有 170+ 條內部連結。** 呢個先係佢啲屋苑頁排到名嘅原因 ——
   唔係每版寫得幾好，係成個網互相扣實。
3. **唔止一種分類法。** 除咗地區，仲有校網、樓齡、呎價、物業類型。
   每一個組合係一版，而每一版對應人真係會打嘅一句搜尋。
4. **啲數會郁。** 成交記錄日日更新，Google 當佢係活嘅網站。

**我哋抄唔到、亦都唔應該抄嘅：**

佢喺 2005 年開，二十年外部連結同域名權重。呢個買唔到、等唔快。
佢啲成交價、佢啲屋苑描述係佢嘅內容。

## 二、所以我哋唔應該同佢爭同一句

搜「**太古城**」—— 28Hse、中原、美聯已經佔晒。我哋一個新域名去爭，輸硬。

搜「**太古城 風水**」「**太古城 坐向**」「**長安邨 風水評分**」—— **冇人做緊**。

> 應該做嘅係：**唔好去爭屋苑名，去爭「屋苑名 + 風水」。**
> 前者係佢哋嘅主場，後者係我哋唯一有嘢講嘅地方。

呢個亦都係做得贏嘅原因：嗰句搜尋嘅答案，全香港得我哋一個計咗出嚟。

## 三、政府開放數據：搵到啲乜

- **129 個欄位**
- **連埋邊界圖形（polygon）** —— 所以可以用座標點對面嚟配，唔使靠撞名
- ArcGIS REST API，即時查得，唔使申請

**大發現：540 個入面有 274 個係我哋而家完全冇 group 到嘅私人屋苑** ——
太古城、淘大花園、荃威花園、碧瑤灣、香港仔中心……

我哋而家淨係公屋居屋有屋苑概念（409 個），因為得房委會個登記冊。
用人口普查嗰啲 polygon 做點對面，私樓第一次有得 group。呢個唔止係 SEO，
係 app 本身嘅窿：而家打「太古城」搵唔到一個屋苑，只搵到散裝樓宇。

撞名試過：409 個入面 266 個直接對到（65%）。用 polygon 會高好多。

## 四、有啲嘢我建議唔好放上版

人口普查有得俾，唔代表應該擺。呢幾個欄位我建議唔要：

- **住戶收入中位數**
- **族裔分佈**
- **出生地**

唔係因為犯法 —— 係公開數據，擺得。係因為**一版叫「XX 屋苑風水評分」嘅頁，
擺埋「呢度住嘅人幾多錢一個月、係邊度人」，件事就由「呢個地方點」變成
「呢度啲人係點」**。嗰條線一過，個網就唔再係我哋講緊嗰樣嘢。

**建議擺嘅：** 單位面積中位數、住戶數、平均住戶人數、落成年份、座數、
單位數目、最近嘅學校/港鐵/公園/醫院。呢啲答嘅係「呢個地方係點」。

## 五、建議做嘅嘢

**頁面結構（學 28Hse 嗰個三層 + 麵包屑）**

```
/                          地圖（已有）
/district/                 18 區總覽                      ← hub
/district/葵青區            區頁：排名、格局分佈、區內屋苑  ← 每版 30–60 條內部連結
/estate/長安邨              屋苑頁：逐座排名 + 普查資料      ← 正菜
```

**規模：18 + 540 = 558 版。** 唔好再多。

逐幢樓開版（84,720 版）會踩正 Google 2026 年 scaled content abuse ——
同一個模斬八萬次，會**全站降權**，連而家 3 版都保唔住。

**每版一定要有：**
- `<title>` 用人真係會打嗰句：`長安邨風水評分 — 10 座逐座坐向、格局｜香港風水地圖`
- 麵包屑（連埋 schema.org BreadcrumbList）
- 一張逐座嘅表，真數據
- 去返地圖嘅連結（頁 → app 嘅轉換）
- 同一個區其他屋苑嘅連結（互相扣實）
- 同一句 disclaimer

**一定唔好有：**
- 換個名就重複嘅 AI 廢話段落。呢樣就係 scaled content abuse 本身。
- 抄返嚟嘅屋苑描述。

## 七、後尾先發現嘅嘢

### 7.1 中原同 28Hse 自己出開放數據

唔使抄。兩間公司自己喺 data.gov.hk 出咗：

| | 內容 | 數量 |
|---|---|---|
| `centaline-centanetod-ccipropertyinfo` | 屋苑名、地址、**發展商**、落成年、座數 | 150 |
| `28hse-opendata-epi-constituent-estates` | 屋苑名、地址、**發展商**、座數、**單位總數** | 148 |

合併 163 個。美聯冇出（3,820 個數據集嘅目錄掃過，冇）。

發展商兩邊 cross check：初頭 129 個「唔夾」，正規化之後剩 **3 個**真分歧。
唔夾嘅原因係寫法（恒基兆業／恒基地產）同埋 28Hse 只列牽頭嗰間，中原列齊。
真分歧兩個講法都列，唔扮知道邊個啱。

### 7.2 成交數據嘅源頭

**源頭係土地註冊處。** 但佢免費公開嘅只係**每月總數**；逐個單位嗰啲喺
IRIS 查冊系統，**要畀錢**。代理買緊批量餵送 —— 唔係秘密渠道，係畀咗錢。

免費而且逐個單位嘅，得房委會嗰批：**居屋／綠置居成交 41,383 宗，72 個屋苑**，
有座、樓層、實用面積、成交價、日期。啱啱好就係我哋覆蓋得最好嗰種樓。

土地註冊處自己嗰 10 個分區對唔正 18 區議會分區，所以**只有對得正嗰 7 個**
（離島、北區、西貢、沙田、大埔、屯門、元朗）先喺區頁出成交數字。

### 7.3 圖點解可以有

地產網嗰啲屋苑相係佢哋嘅。但**地政總署嘅航空影像係開放數據**，而且
我哋個地圖本來已經用緊同已經註明。航空圖 + 我哋自己嘅樓宇輪廓 + 分數上色
＝ 一張人哋冇嘅圖。

**驗證方法**（圖對唔對得正幢樓）：

1. **投影** —— 對照 `worker/index.js` 入面獨立寫過一次嘅實作，加三個
   用腦算得到嘅定點。投影錯會令所有圖一齊錯，逐個屋苑檢查係捉唔到嘅。
2. **對位** —— 航空圖入面天台同地面唔同色。量輪廓內外嘅顏色差距：有樓
   就有差距，落咗喺空地就冇。
3. **反向對照** —— 刻意將輪廓推開 20 米再量。擺正 14.3–58.1，推開
   4.4–12.1，**兩組完全唔重疊**，所以門檻定 13。一個永遠 pass 嘅檢查
   等於冇檢查過。

驗唔過嘅屋苑**唔出圖**。冇圖蝕少少，畫錯位係對住人哋間屋講咗錯嘢。
